# telegram-claude-bot

Telegram-бот-секретарь для фрилансера Азизхона (Untra.dev). Node.js 18+, ESM,
без фреймворков. Бизнес-сообщения клиентов → черновик ответа владельцу с
кнопками ✅/🗑 (или автоответ по правилам), плюс задачи, напоминания, сводки
по чатам и разбор дня для постов.

## Карта файлов

- `src/bot.js` — long polling, роутинг апдейтов, все команды владельца, очередь автоответов.
- `src/claudeClient.js` — вызов Claude (`claude -p` или Anthropic API), сессии `--resume`, парсинг ответов моделей.
- `src/raphael.js` — Рафаэль-менеджер: системный промпт (сначала постоянное — персона, знания, правила; в конце живое состояние — для кэша), липкие стратегии, «что было с прошлого ответа» в начале сообщения, ротация сессии (20 ч / 40 ходов), подгрузка переписок по `[[CHAT: имя | с ДД.ММ.ГГГГ | N]]` (по умолчанию 120 сообщений, период — дословно; сжатие ролью reader только если больше ~400k символов), сессии /day.
- `src/knowledge.md` — общие знания об Азизе и боте для Рафаэля и /day.
- `src/importer.js` — разбор экспорта Telegram Desktop (result.json).
- `src/config.js` — чтение `.env`, дефолты.
- `src/state.js` — вся персистентность в `data/state.json` (история, черновики, задачи, автоответы).
- `src/telegram.js` — тонкая обёртка над Bot API.
- `src/persona.md` — персона и прайс для автоответчика клиентам.
- `src/assistant-persona.md` — персона личного секретаря (не путать с автоответчиком).
- `src/content-persona.md` — персона для `/day` (разбор дня → посты в каналы).
- `src/templates.js` — фиксированные шаблоны для intent refusal/soft_no/examples.
- `src/prices.js` — единственный источник разрешённых цен (в сумах) и проверка сумм в тексте.
- `src/commands.js` — единственный источник списка команд для `/help` и `setMyCommands`.
- `src/media.js` — голосовые/кружки → текст (Groq Whisper), фото → картинки, видео → кадры + звук (ffmpeg).
- `src/format.js` — markdown-lite от Рафаэля → HTML Telegram, нарезка длинных ответов.
- `src/stream.js` — стриминг ответа в Telegram (первое сообщение сразу, дальше редактирование ~раз в 1.5 с, в конце HTML).
- `src/models.js` — модель одна (Opus 5.5, `BOT_CLAUDE_MODEL`), effort по ролям (raphael, day, clients, filter, writer; дефолт `BOT_CLAUDE_EFFORT=low`), команда /model, хранение в state.json.
- `src/strategies.js` + `src/strategies/*.md` — стратегии продвижения по площадкам и правки владельца (в state.json, файлы не переписываются).
- `src/mtproto.js` — userbot аккаунта владельца (пакет `telegram`/gramjs): чтение любых чатов, поиск/чтение публичных каналов, отправка комментария (только из кнопки владельца).
- `src/comments.js` — агент комментариев: поиск каналов, watchlist, мониторинг постов, фильтр + писатель, карточки ✅/👤/✏️/🗑, очередь отправки с лимитами.
- `src/reddit.js` — подборка вопросов с Reddit (публичный JSON) + черновики ответов; отправляет владелец сам.
- `src/planner.js` — напоминания по расписанию (Ташкент): посты и комментарии на Telegram/Contra/LinkedIn/Reddit, адаптации постов, утренняя сводка, воскресный отчёт.
- `src/team.js` — Рафаэль и бот как команда: сводка состояния бота и журнал событий для Рафаэля, локальный роутер простых фраз без Claude, общая память для агентов.
- `src/rewrite.js` — переделка черновиков (✏️, reply на карточку, [[REWRITE]] от Рафаэля), правки/правила для автоответчика (clientRulesText).
- `scripts/mtproto-login.js` — одноразовый вход в аккаунт → строка TG_SESSION (`--qr` — вход по QR).

## Команды разработки

- Запуск: `npm start` (нужен заполненный `.env`, см. `.env.example`).
- Офлайн-тесты агента (парсеры, фильтры, расписание, стратегии, модели): `npm run test:agent` (`-- --live` — ещё и живой стриминг).
- Тесты классификатора intent: `npm run test:intents`. Режим /day: `npm run test:day`. Медиа и форматирование: `npm run test:media`. Рафаэль (память, чаты, интернет): `npm run test:raphael`.
- Синтаксис после правки файла: `node --check src/<файл>.js`.
- `DRY_RUN=true` в `.env` — ничего не уходит клиентам (ни автоответ, ни ✅), только лог/уведомление владельцу. Использовать при любой ручной проверке.

## Общая система untra

Прайс, знания об Азизе и стратегии площадок собираются из `~/Public/untra` скриптом `python3 build.py --bot <путь к боту>`. Блоки между `UNTRA:BEGIN` и `UNTRA:END` (persona.md, knowledge.md, prices.js) и файлы `src/strategies/{overview,contra,linkedin,reddit,telegram}.md` руками не править: правки делать в untra и пересобирать.

## Правила кода

- Строго ESM (`import`/`export`), без CommonJS.
- Новые npm-зависимости — только после явного согласия, не добавлять по своей инициативе.
- Маленькие изменения за шаг, проверять `node --check` сразу после правки.
- Не переписывать рабочий код без причины (не рефакторить попутно).

## Правила бизнеса

- Все цены — только из `src/prices.js`, в сумах. Если суммы в тексте нет в списке — не автоотправлять.
- Скидка максимум 10% от цены за тот же объём. Оплата по этапам (30/40/30 или Contra milestones), каждый этап — до начала работы. Подробно — блок UNTRA в persona.md.
- Бесплатно ничего не делаем: ни дизайн, ни прототип, ни ТЗ.
- Стиль сообщений клиентам: на «вы», коротко, простыми словами, без канцелярита и списков, без давления и дожима, не обещать функции, которых нет в продукте.

## Запреты

- Не открывать и не выводить содержимое `.env`, `.env.local`, `data/state.json` и остального `data/`.
- Не менять песочницу (`sandboxDir`). Автоответчик клиентам и /day — только `--allowedTools ""` (защита от prompt injection из чужих сообщений). Рафаэлю (личный чат владельца) разрешены только `WebSearch,WebFetch` — никаких файловых инструментов и Bash. Вдобавок `--tools` (тот же список) — остальные инструменты даже не описываются модели, и `--system-prompt-file` вместо стандартного промпта Claude Code (экономия ~24k токенов на вызов). Не возвращать `--append-system-prompt-file` без причины.
- При любом тестировании — только `DRY_RUN=true`, никогда не отправлять реальные сообщения клиентам.
- Агент (фильтр постов, писатель комментариев, адаптации постов, Reddit) — только через `runOneShot` без инструментов: чужие посты = недоверенный ввод.
- MTProto: действия от аккаунта владельца (вступить, отправить комментарий) — только из обработчика кнопки владельца, с дневными лимитами (MAX_COMMENTS_PER_DAY, MAX_JOINS_PER_DAY) и блокировкой в DRY_RUN. FLOOD_WAIT — ждать, не ретраить в цикле. TG_SESSION нигде не логировать и не сохранять в state.json.

## Рабочий процесс

План → «ок» от пользователя → код → тесты (`node --check`, `npm run test:intents`) → короткий итог. Если что-то неясно в задаче — спросить, не угадывать.

## Модели

- Основная работа по коду — Sonnet.
- Поиск по коду, простые проверки — субагенты на Haiku/Sonnet (`code-explorer`, `tester` в `.claude/agents/`).
- Opus для кодинга не использовать.
